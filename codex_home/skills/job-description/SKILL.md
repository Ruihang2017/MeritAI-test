# Job description / job ad

## Inputs to gather

Work from whatever the user gives. The essentials are: role title, team or business unit, location, employment type (full-time / part-time / casual / fixed-term), and the 3-5 things the role is mainly for. If any essential is missing, use a placeholder like [Location] and list the missing items in one line at the end. Do not stop to ask unless the role itself is unclear.

Optional inputs, use if provided: reporting line, salary range or band, shift pattern or roster, required licences or certifications, travel, physical requirements.

## Output

Default to a full position description. If the user asks for an ad, write the ad version instead (shorter, candidate-facing, benefits first).

Position description structure:

1. Title line: Role title, Location, Employment type
2. About us: 1-2 sentences based only on the business profile (name, what the business does, where). If there is none, write [About the business]. Never add claims that are not in the profile (no "leading", "award-winning", size or history).
3. About the role: 2-3 sentences on the role's purpose and impact, based only on what the user said about the role
4. Key responsibilities: 5-8 bullets, each starting with a verb, specific and observable
5. About you (selection criteria), split into Essential and Desirable. Essential: only what is genuinely required on day one. Desirable: everything else.
6. What we offer: [Salary range / pay rate] plus every benefit from the business profile that applies to this role (list each one), plus any benefits the user supplied. Mention work from home only if the user or profile says the role allows it.
7. An equal opportunity line: the business's own statement if the profile or policies have one, word for word; otherwise a short general line such as "We welcome applications from people of all backgrounds."

Job ad structure: hook (1-2 sentences about the role, not the company), why join (the benefits from the business profile that apply, and about the business only what the profile says), what you'll do (4-6 bullets), what you'll bring (4-6 bullets), benefits, how to apply [Apply link / instructions], equal opportunity line.

## Language rules

- Plain Australian English, second person ("you'll"), active voice.
- Languages: require only clear written and spoken English unless the user says the role needs another language (e.g. serving customers in Mandarin). Never add a language requirement because the user is writing to you in that language.
- Inclusive wording. Avoid gender-coded or age-coded terms: "rockstar", "ninja", "young and dynamic", "digital native", "recent graduate" (unless it is a graduate program), "he/she". Avoid "native English speaker"; say "clear written and spoken English" if language matters for the role.
- Years of experience: prefer capability ("experience leading a team of 5+") over tenure ("10+ years"). If the user insists on years, use a range and keep it in Desirable where possible.
- Physical requirements: only state them if they are inherent requirements of the role, and describe the task ("regular lifting up to 20 kg"), not the person.
- Keep degree requirements only when the role genuinely needs them.

## When improving an existing JD

Return the improved version first, then at most 5 bullets titled "What I changed" covering the substantive changes (e.g. removed age-coded wording, moved X to Desirable, added missing location). Flag any requirement that could be discriminatory and suggest a job-related alternative.
