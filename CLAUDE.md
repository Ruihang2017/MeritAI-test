# CLAUDE.md

A CLI HR adviser for small business owners with no HR department ("tells them what to do and gets it done"). It covers the business profile, recruitment, onboarding, performance, difficult conversations / ER and offboarding. It is an internal POC, tested by the Coates HR team playing small business owners. TypeScript (Node 22+, `tsx`), wrapping a local `codex app-server` over stdio JSON-RPC. User docs: `README.md`. Design (as built): `docs/architecture.md` (layers, AssistantApp API), `docs/business.md` (profile, policies, hiring, register, reminders, award), `docs/screening.md`, `docs/memory.md`, `docs/research.md`, `docs/files.md`, `docs/voice.md`; manual test script: `docs/manual-test.md`. Agreed plans not yet built: `docs/plans/`.

## How we work

- The project owner steers step by step. Build only the step agreed in the conversation. When they say "先讨论/不写" (discuss first, don't write), discuss and plan without editing files.
- Docs describe what is built. No PRD or long-range roadmap. The one exception is `docs/plans/`: plans the owner has explicitly agreed or asked for, each with a status line. When a plan is built, move its content into the as-built docs (`README.md`, `docs/*.md`, this file) and delete the plan file. Update `README.md` and `docs/*.md` whenever behaviour changes.
- The owner writes in Chinese; reply in Chinese.
- Layering: new behaviour goes into the core modules or `src/app/app.ts`; `src/cli.ts` only renders and parses (a desktop UI will reuse the app layer). See `docs/architecture.md`.
- After a change, run what it touches (voice test only for voice changes; see Paid API cost): `npm run typecheck`, then `npm run e2e`, `npm run test:skills`, `npm run test:memory`, `npm run test:research`, `npm run test:files`, `npm run test:hr`, `npm run test:screening`, `npm run test:business`, `npm run test:hiring`, `npm run test:register`, `npm run test:reminders`, `npm run test:award` or `npm run test:voice`; `npm run test:unit` is free (no model calls), so run it after every change. These call the real model, take 1–5 minutes each, and use synthetic data.

## Constraints

- **Never invent facts about the business** in prompts, skills or examples; they come from the profile. Test data uses the synthetic "Wattle Lane Cleaning" business (`scripts/fixtures/`), marked as synthetic.
- The chatbot is logged into the owner's **personal ChatGPT Plus** account. Use no real candidate or employee data until it uses a company-approved account (`OPENAI_API_KEY` + `npm run login`). The same applies to voice: audio and transcripts go to the OpenAI organisation of `VOICE_OPENAI_API_KEY`.
- The app-server protocol is experimental. After upgrading `codex`: `npm run gen:protocol`, `npm run inspect` (check that no capability reappeared), then all test suites.
- **Paid API cost:** `npm run test:voice` and `/voice` bill the owner's OpenAI key (GPT-Live, US$0.05/min). One test run is about 2 minutes (about US$0.10); the test prints the billed seconds at the end. By 2026-09-25 about 17 voice-test runs had cost about US$1.70 of US$2.10 total; 1 more run that night (after the small-business `voice.md` change) billed 123 s, about US$0.10. Run it only when voice code (`src/voice/`, `prompts/voice.md`) changes, once, and not in routine regressions. Ask the owner before repeated runs. The Codex suites use the owner's ChatGPT Plus quota (no charge per run, but limited), so run only the suites a change touches.
- Prompt rules are probabilistic. Test suites call the real model, so an occasional single failure can be model variance: rerun, and look at the printed reply before changing prompts. Anything that must always hold needs a client-side check (e.g. the PII filter, domain allowlist, unverified-link guard), not just a prompt rule.
- On `thread/resume`, the server ignores new developer instructions. Fresh memory is sent as a `<memory_update>` prefix on the next message.
